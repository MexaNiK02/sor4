# Принцип работы LiveQuiz MVP

Этот файл описывает устройство проекта: как работает приложение, какие части за что отвечают и где искать основную логику.

## Общая идея

Приложение состоит из Laravel API и React-интерфейса.

Laravel отвечает за:

- регистрацию и вход ведущих;
- регистрацию участников;
- роли `host`, `admin` и `participant`;
- хранение квизов, вопросов, ответов, игровых сессий и участников;
- проверку прав доступа;
- таймеры вопросов;
- подсчёт баллов;
- историю игр;
- CSV-экспорт.

React отвечает за:

- кабинет ведущего;
- редактор квизов;
- экран игровой сессии ведущего;
- вход участника по коду;
- экран ответа участника;
- личный кабинет участника с историей игр;
- итоговый рейтинг после игры.

Node.js WebSocket-сервер `websocket-server.js` отвечает за:

- подписку ведущего и участников на игровую сессию;
- синхронизацию старта, переключения вопросов и завершения;
- секундные события таймера;
- приём ответов участника через WebSocket и передачу их в Laravel API;
- рассылку событий о новых участниках и новых ответах.

## Пользовательские сценарии

### Ведущий

1. Регистрируется или входит в аккаунт.
2. Создаёт квиз.
3. Запускает игровую сессию.
4. Показывает участникам код или QR.
5. Начинает игру.
6. Может переключать вопросы вручную.
7. После игры смотрит историю и экспортирует CSV.

Ведущий видит только свои квизы.

### Участник

1. Открывает `/join`.
2. Вводит код сессии и имя.
3. Отвечает на вопросы без регистрации.
4. Может создать аккаунт участника.
5. Если играет из аккаунта, сессия сохраняется в личной истории.
6. После завершения видит личный результат и общий рейтинг всех участников сессии.

### Администратор

1. Входит как пользователь с ролью `admin`.
2. Видит все квизы.
3. Может редактировать любые квизы.
4. Не меняет владельца квиза при редактировании.
5. Удаляет только квизы, созданные им самим.

## Основные папки

### `app/Http/Controllers/Api`

Здесь находятся API-контроллеры.

- `AuthController.php` - регистрация, вход, текущий пользователь, выход, история зарегистрированного участника.
- `QuizController.php` - список квизов, создание, редактирование, удаление, запуск сессий, история игр по квизу.
- `SessionController.php` - управление live-сессией: старт, следующий вопрос, завершение, статистика ответов, лидерборд, CSV-экспорт.
- `ParticipantController.php` - действия участника: статус игры, отправка ответа, итоговый результат.

### `app/Http/Middleware`

- `AuthenticateApiToken.php` - простая авторизация API по Bearer-токену ведущего или администратора.

Токен хранится в таблице `users` в поле `api_token`.

### `app/Models`

Eloquent-модели базы данных.

- `User.php` - ведущий, администратор или зарегистрированный участник. Содержит роль, токен и связи с квизами/сыгранными сессиями.
- `Quiz.php` - квиз, принадлежащий пользователю.
- `Question.php` - вопрос квиза, тип вопроса и до 4 ссылок на картинки.
- `Answer.php` - вариант ответа.
- `GameSession.php` - live-сессия квиза. Здесь находится важная логика таймера и автоматического перехода.
- `Participant.php` - участник конкретной сессии.
- `ParticipantAnswer.php` - ответ участника на вопрос, включая один или несколько выбранных вариантов.

### `database/migrations`

Миграции создают таблицы:

- `users` - аккаунты ведущих и администраторов;
- `quizzes` - квизы;
- `questions` - вопросы;
- `answers` - варианты ответов;
- `game_sessions` - игровые сессии;
- `participants` - участники сессии;
- `participant_answers` - ответы участников.

### `database/seeders`

- `DatabaseSeeder.php` создаёт демо-администратора, демо-ведущего и пример квиза.

### `routes`

- `routes/api.php` - все API-маршруты.
- `routes/web.php` - отдаёт React-приложение для всех web-страниц.

### `resources/js`

React-фронтенд.

- `App.jsx` - основное приложение, все страницы и компоненты интерфейса.
- `lib/api.js` - обёртка над `fetch`, автоматически добавляет Bearer-токен ведущего.

Основные React-экраны внутри `App.jsx`:

- `Home` - главная страница.
- `AuthPage` - вход и регистрация ведущего.
- `HostDashboard` - кабинет ведущего и администратора.
- `QuizBuilder` - создание и редактирование квиза.
- `SessionRoom` - экран ведущего во время игры.
- `JoinPage` - вход участника по коду.
- `ParticipantPlay` - экран участника во время игры.
- `ResultPage` - личный результат и общий рейтинг после игры.

### `resources/css`

- `app.css` - все стили интерфейса.

### `public`

Публичная папка Laravel. На VPS веб-сервер должен смотреть именно сюда.

- `public/index.php` - точка входа Laravel.
- `public/build` появляется после `npm run build`.

### `config`

Настройки Laravel. Важный файл:

- `config/database.php` - настроен SQLite с поддержкой относительного пути `database/database.sqlite`.

### `storage`

Служебная папка Laravel для кеша, сессий, логов и временных файлов. На Linux у веб-сервера должны быть права на запись в эту папку.

## Как работает WebSocket-синхронизация

WebSocket-сервер находится в файле `websocket-server.js` и запускается командой:

```bash
npm run ws
```

Фронтенд подключается к `VITE_WS_URL`, по умолчанию это:

```text
ws://127.0.0.1:6001
```

Laravel отправляет события в WebSocket-сервер через HTTP hook `LIVEQUIZ_WS_HOOK`, по умолчанию:

```text
http://127.0.0.1:6001/broadcast
```

События используются для обновления экранов ведущего и участника: старт игры, новый вопрос, завершение, новый участник, новый ответ и секундный tick таймера. Если WebSocket-сервер временно недоступен, Laravel продолжит работать, но live-обновления в браузере не будут мгновенными.

## Как работает таймер вопросов

Главная логика находится в `app/Models/GameSession.php`.

У сессии есть фаза:

- `waiting` - участники подключаются;
- `question` - идёт вопрос и можно отвечать;
- `reveal` - 5 секунд показывается результат и правильный ответ;
- `finished` - игра завершена.

Когда фронтенд периодически запрашивает статус сессии, backend вызывает `refreshTimedState()`. Этот метод проверяет время:

1. Если время вопроса вышло, сессия переходит в `reveal`.
2. Если 5 секунд reveal прошли, сессия переходит к следующему вопросу.
3. Если вопросов больше нет, сессия завершается.

Поэтому отдельный cron или WebSocket для MVP не нужен: состояние обновляется при регулярных запросах от ведущего и участников.

## Как считаются баллы

Логика ответа находится в `ParticipantController.php`, метод `answer()`.

Для `single_choice` участник выбирает один вариант.

Для `multiple_choice` участник выбирает несколько вариантов. Ответ считается правильным только если набор выбранных вариантов полностью совпал с набором правильных вариантов.

Если ответ правильный:

- базово даётся 100 баллов;
- дополнительно даётся бонус за скорость до 50 баллов.

Если ответ неправильный:

- даётся 0 баллов.

Рейтинг сортируется по баллам по убыванию.

## Как работает история игр

Каждый запуск квиза создаёт запись в `game_sessions`. Участники и их ответы связаны именно с этой сессией. Поэтому у одного квиза может быть много игровых сессий.

История выводится в кабинете ведущего через endpoint:

```text
GET /api/quizzes/{quiz}/sessions
```

CSV-экспорт доступен через:

```text
GET /api/sessions/{session}/export.csv
```

CSV отдаётся в UTF-8 с BOM и разделителем `;`, чтобы Excel корректно открывал русские буквы.

## Как устроены права доступа

Открытые маршруты:

- регистрация ведущего;
- вход ведущего;
- вход участника в сессию;
- статус участника;
- отправка ответа участника;
- результат участника.

Закрытые маршруты:

- CRUD квизов;
- запуск сессий;
- управление сессиями;
- история игр;
- CSV-экспорт.

Закрытые маршруты требуют Bearer-токен ведущего или администратора.

## Как заменить SQLite на другую базу

Нужно поменять `.env`. Код приложения уже использует Eloquent и миграции Laravel, поэтому переход на MySQL или PostgreSQL не требует переписывания бизнес-логики.
